## 一、为什么出这个包

实装报错（两轮）：

```
[Round 1] Object is not iterable (cannot read property Symbol.iterator)  ← Set/Map 迭代器
[Round 2] 同一条报错换了位置                                              ← Map 迭代器第二次扫描才找到
```

**根因**：Bloxd 代码块引擎的 Set / Map **没有 Symbol.iterator**。
任何 `for...of Set/Map`、`[...set]`、`[...map.keys()]`、`[...map.entries()]`、
`[...new Set(arr)]`、`set.values().next()` 都会崩溃。

**影响（24 处，覆盖 5 个文件）**：

| 文件 | 崩溃点 | 修复 |
|------|--------|------|
| game.js | G.players / markerMaps / SPAWNABLE_MOBS / mutedPlayers（12 处） | `Map.forEach` / `setToArray` / `unique` helper |
| team.js | team.members / pendingInvites（7 处） | `Map.forEach` / `setToArray` helper |
| loot.js | chestCooldowns / insuredSlotsOf 去重（3 处） | `Map.forEach` + 对象去重 |
| customweapons.js | registry 武器注册表（1 处） | `Map.forEach` |
| menu.js | 撤离点类型去重（1 处） | `Array.forEach` + 对象去重 |

**安全**：数组 `for...of`（`for (const it of array)`）和 `Object.entries()` 返回数组的迭代 Bloxd 支持，本次未动。

## 六、代码状态说明

本包仍是 CommonJS `require("./xxx.js")` 写法（Bloxd 代码块唯一支持的模块系统），
没有改成 ESM，没有三路径兼容层，没有诊断逻辑。

Set / Map / 迭代器的全面修复是**永久化**的 —— 以后加新功能也必须遵守：
- Set / Map 只用 `.forEach()` / `.has()` / `.get()` / `.set()` / `.delete()` / `.size` / `.add()`
- **禁止** `for...of`、展开 `[...set]`、`.keys()` / `.entries()` / `.values()` 返回的迭代器
- 去重用 `unique(arr)` helper，不用 `[...new Set(arr)]`
